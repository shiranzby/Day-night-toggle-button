# 长页面主题切换：根因、修复与移植指南

这份文档整理自 2026-10-15～16 的 shydoc 长文档站适配，并于 2026-10-19 补充点击坐标及固定面板视觉回归。它是一个经过多轮定位与验证的案例，不是所有网站都要照搬的配置，也不保证任何手机都能达到相同耗时。

核心结论：**卡顿主要不在太阳/月亮按钮本身，而在按钮触发后，宿主页面承担的全局样式重算、视图快照、布局及观察器计算。** “内容已经加载”也不意味着“下一次显示没有渲染成本”。

## 1. 先分清四层职责

| 层 | 负责什么 | 不应承担什么 |
| --- | --- | --- |
| 按钮外观 | Shadow DOM 内的太阳、月亮、云朵、悬停及按下动画 | 扫描整页正文、替宿主选配色、控制目录布局 |
| 主题状态 | 当前亮/暗状态、用户偏好、系统跟随、持久化、通知按钮 | 同时存在多个互相覆盖的状态源 |
| 页面揭示 | 原生 View Transition（下文简称 VT），或轻量圆盘与局部颜色波 | 在所有页面、所有设备上强行使用同一渲染路径 |
| 页面结构 | 代码高亮、图片占位、局部滚动、侧栏与长文布局 | 指望更换按钮就消除既有的超大 DOM 或布局问题 |

本案例也移除了按钮内常驻云朵定时器，并把跟随鼠标的交互限定在可悬停、精细指针设备；这是减少后台与无效事件工作的小优化，不是上述秒级冻结的主要修复。

推荐因果检查链：

```text
点击按钮
  → 状态变更（只认一个状态源）
  → 页面主题属性 / CSS 变量改变
  → 样式重算 → 必要布局与绘制
  → VT 快照或轻量揭示
  → 背景落定、移除覆盖层、恢复临时样式

旁路：滚动 / 图片加载 / 抽屉动作
  → 是否真的改变正文几何？
  → 只有确实改变时，才使颜色波缓存失效
```

真实浏览器内部的任务可能交错执行；这条链用于归因，不是浏览器实现的严格时序图。

## 2. shydoc 的问题、修复及移植边界

| 症状 | 已定位的原因 | 已采用的方法 | 移植时必须检查的边界 |
| --- | --- | --- | --- |
| 涟漪首击偏向默认点、下一击追着上一次点击或键盘沿用旧点 | 按钮先注册capture click并同步派发change，控制器后注册的同宿主capture click尚未保存本次坐标；iframe桥曾重复此错误 | 在按钮的change事件上携带本次 `event.point`，保留detail字符串；控制器和桥直接读取，不再缓存晚到的click | 用真实点击按钮两端复验；视口client坐标不加滚动量或DPR；键盘/程序click为null；不要把此独立事件问题误诊为渲染慢 |
| 点击后明显停顿 | 原章节约 11 万个代码 token `span`；主题规则让大量节点重新匹配 / 计算颜色 | 构建期删除确实无样式、无语义的高亮包装；减少逐 token 的主题依赖；代码块离屏时跳过内容渲染 | 只能删除由高亮器生成、确认无样式和行为的包装；不得删原文、可访问语义、插件挂点或自定义配色 |
| 涟漪只出现少数几帧，手机冻结数秒 | 原生 VT 的根视图捕获及相关渲染在超长 DOM 上阻塞；桌面样本不能代表手机 | 长页手机路径绕过 VT，使用 fixed 裁剪层中的圆盘，以及视口附近正文颜色波；桌面保留已验证的 VT | 不是“VT 一定慢”；必须以目标页面和设备实测决定。超长页不要通过 `body{position:fixed}` 锁页来压缩快照 |
| 增加超时仍卡住 | watchdog 与渲染长任务共用主线程；长任务期间定时器也无法运行 | 在已知不适合的环境里事先选择轻量路径；超时只作为能获得执行机会时的异常收束 | `Promise.race`、`setTimeout` 不能抢占同步长任务，不能当硬性性能上限 |
| 开启 `content-visibility` 后远处锚点偏移 | 跳过块的估计高度不准，导致全文高度和滚动定位错误 | 对不折行代码，构建期写出行数，以固定、量化后的行高计算准确 content-box 占位；打印恢复完整渲染 | 仅适用于行数可确定、`white-space:pre`、固定行高的代码。换字体、换行高、自动折行、附加行号 / 工具栏都要重新验证；不要照抄本案例的 `20.796875px` |
| 图片懒加载时页面跳动，缓存反复重建 | 未知固有尺寸使图片加载后改变后续正文位置 | 构建期读取宽高；用固定比例外框持有几何，图片绝对定位填入，成功与失败都不改变占位 | 只有外框真正保证几何不变，才能跳过该图片的加载失效通知；未知尺寸图片仍要更新 |
| 主题结束的最后一瞬间全屏闪亮 / 闪暗 | 圆盘已淡出，底层背景仍在延迟颜色过渡中；合成色短暂偏离目标 | 圆盘保持不透明；背景颜色落定后跨两次 `requestAnimationFrame` 再移除；固定裁剪层与内容层级保持稳定 | 不能只看结束后的 computed color。要看末段实际合成画面；双 rAF 是绘制交接手段，不保证两个物理显示帧 |
| 快速反切出现残留过渡或旧动画误删新圆盘 | 清理用 truthy 判断漏掉原本为空字符串的 inline 值；旧异步回调仍能执行 | 显式区分“未保存”与“保存为空”；取消前解绑旧回调；用当前动画 / token 身份保护清理 | 必须测连续点击、反切、取消、异常和卸载；结束后恢复宿主原样式，而非一律清空 |
| 手机右侧空白、页面被缩小 | 普通 `pre` 长行没有局部横滚，撑大布局视口 | 代码框限制宽度并使用内部 `overflow-x:auto`，而非在页面根节点隐藏溢出 | 同时看根 `clientWidth`、`scrollWidth`、`innerWidth` 和 `visualViewport.scale`；保留代码内容可横滚 |
| 打开目录或首次切大纲卡顿 | 不是下载问题：内容已在 HTML 中。全章主题观察器每帧计算大量相交关系；隐藏页签首次显示又触发根布局 | 仅观察视口附近正文；目录 / 大纲常驻、预布局、独立滚动，切换可见性和可交互性 | 隐藏页签必须不可点击、不可聚焦；预布局会占内存，要权衡面板规模；不能把整个正文都强制预布局 |
| 主题切换期间抽屉瞬跳 | 逐元素颜色波的 inline `transition` 覆盖了侧栏原有 `transform` 过渡 | 将侧栏排除出正文观察；滑动只由自己的 `transform` 控制。面板配色由宿主的独立局部揭示负责 | 解耦不等于取消侧栏揭示；不要给所有节点写同一个 transition 或覆盖根面板的 transform |
| 目录先整块变色、可见圆弧像从按钮下方出现 | 侧栏直接响应新变量；不透明高层顶栏挡住低层圆盘。shydoc 原圆盘实测中心与点击一致，不能凭圆弧观感随意偏移坐标 | 宿主为顶栏/侧栏背景增加同圆心、同半径曲线的伪元素裁剪；一次索引面板行，只二分定位当前可见行，用相同贝塞尔曲线反求颜色到达时间，不加入正文 IO | 这是宿主层适配，不是共享控制器已自动处理所有侧栏。需检查面板滚动、堆叠、transform、快速反切和异常清理；新显示内容可直接采用当前主题，不承诺移动面板的逐帧快照等价 |
| 抽屉动作仍引起不必要正文计算 | 开关、页签和侧栏内部滚动错误地使正文缓存失效 | 删除抽屉动作到正文缓存的关联，打开只改变局部 class / 可见性 | 大纲点击若真正引发正文滚动，该滚动仍应更新正文缓存 |
| 隐藏内容、代码横滚、定尺寸图加载仍在耗费计算 | 观察目标与失效条件过宽 | 不收集 `display:none` 根块；代码块内部滚动不重建正文缓存；固定框图片加载不重建 | resize 后可见内容要重新纳入；表格单元格横移、未知图增高仍会改变目标位置，必须保留更新 |

### 不应变成通用默认的历史试验

- 整块 `filter:invert(1) hue-rotate(180deg)` 曾用于减少代码逐 token 主题切换，但它会改变原始配色，并带来栅格化成本。不要对图片、品牌色、任意代码主题或整页盲目反转；若要求精确双主题，应使用宿主自己的配色并验证对比度与性能。
- 动画优先改变 `transform`，有利于合成，但不代表整个页面“不重绘”或“必定由 GPU 免费完成”；颜色变化和 filter 仍可能产生绘制成本，以 trace 为准。
- 删除无色包装、精确代码占位、固定图片外框等是**宿主生成器优化**，不应藏进按钮组件，在运行时擅自改写任意网站正文。
- 页面的 `.prose`、`.sidebar`、`pre`、`.image-frame` 等只是案例选择器。换一个网站，必须重新确认 DOM、颜色继承、定位方式与滚动容器，不可字符串替换后直接宣称完成。

## 3. 局部颜色波的正确范围与失效关系

轻量路径并非“全章所有节点延时变色”。做法是：在空闲时选择视口附近正文直接子块，收集这些块内需要独立变色的目标，缓存位置；点击只消费缓存，不同步测量整章。远离视口的内容直接落到目标主题，不排队播放不可见动画。

| 来源 | 是否更新正文颜色波缓存 | 理由 |
| --- | --- | --- |
| 正文 / 页面实际滚动 | 是 | 正文目标相对点击点的位置变化 |
| 窗口 resize、正文折叠、正文插入 / 删除 | 是 | 可见范围或文档几何可能变化 |
| 目录开关、页签切换、目录内部滚动 | 否 | 独立常驻面板不改变正文几何 |
| 代码框内部横滚 | 本案例中否 | 代码 token 不参与颜色波，代码框本身未移动 |
| 表格内部横滚 | 本案例中是 | 单元格是配色目标，其横坐标发生变化 |
| 固定比例框内图片加载 | 几何确实不变时否 | 外框已持有全部占位 |
| 未知尺寸图片加载 | 是 | 可能把后续正文推移 |
| 手机隐藏的桌面右大纲 | 不观察；变宽后重选 | 不可见目标无需相交计算，但不能永久删除 |

重要实现约束：

- `IntersectionObserver` 是异步接口，不是零成本接口。观察数千节点，仍可能在每次动画更新时产生显著浏览器工作。
- 二分定位正文直接子块依赖其在普通文档流中按顺序排布。多列、瀑布流、绝对定位正文、虚拟列表或动态重排不能直接使用这个前提。
- 独立延迟变色的目标必须确实拥有对应颜色属性；仅继承父级颜色的子元素无法自动拥有自己的波到达时间。若补显式 `color`，应先证明与原计算值一致，并验证链接、代码、选中态等特殊配色不被覆盖。
- 局部块里如果是单个超大表格 / 列表，观察目标仍可能很多；“附近几个块”不等于严格常量复杂度。
- 缓存失效时断开旧观察器、清掉旧坐标；异步回调要检查当前实例身份。缓存未就绪时允许简化揭示或直接完成主题，不在点击里补做全章扫描。
- 粗指针可以参与揭示路径选择，但不能用来永久排除大纲：宽屏触摸设备上，大纲仍可能可见。

## 4. 历史证据：分别解读，不拼成一个万能跑分

下列数据来自 shydoc 不同阶段的本地报告，页面内容、资源状态和测试配置并不全部相同。文档整理时没有重新运行完整性能实验；数字用于说明已确认的瓶颈与因果对照，不是本仓库组件的统一基准。

| 阶段与条件 | 观测 | 能说明什么 / 不能说明什么 |
| --- | --- | --- |
| 早期 c29，约 41.7 万 px、118,212 个 DOM、110,812 个代码 `span` | 主题翻转相关整帧约 515～658ms；剥离逐 span 暗色规则的诊断副本约 2～17ms | 定位大量 token 的主题依赖；诊断副本不是可直接上线的视觉等价方案，也不能把耗时归为按钮内部动画 |
| 构建期简化高亮包装后 | c29 DOM 118,212 → 45,044，约减少 62% | 减少参与样式与布局的节点；不是删除了 62% 的原文 |
| 项目后补记录 | “主题翻转整帧约 33～51ms” | 本次仅整理该历史补充，未独立复核其完整测量配置；不作为跨设备承诺，不与其他阶段样本合并计算提升倍数 |
| 390×844、DPR2、触摸、CPU4×，手机长页 VT 诊断 | VT 主题 update 延迟约 3.2～3.6s，700ms watchdog 同样等待 | 说明应事先绕过已知昂贵路径；不能由桌面 VT 的较短耗时推断手机也安全 |
| 抽屉修复，Python 3.13.12 / Playwright 1.64.0 / Chromium 151.0.7922.34；390×844、DPR2、触摸、CPU4×，图片等尺寸隔离；前后各两轮 | 首次目录 84.7～98.1 → 32.0～33.7ms；首次大纲 208.5～233.6 → 31.2～36.6ms；首次大纲布局约 114～139 → 0ms | 延迟指标是点击至双 rAF 绘制机会，不是 INP、p95 或真机帧率；trace 为独立诊断样本，不混入计时样本 |
| 抽屉诊断 trace，600ms 操作窗口 | 全章主题观察的 `computeIntersections` 累计约 447～471ms；单轮约 46～63ms | 指向浏览器观察工作，而非网络未预加载；trace 本身不作为独立性能收益统计 |
| 抽屉与正文缓存解耦，c29 / c41 同组操作 | 缓存重建 5 → 0 次，正文位置读取 85 → 0 次；侧栏主题观察目标 46 → 0 | 消除了这一条冗余传递链；不代表浏览器没有绘制、没有其它观察器 |
| 最新观察范围对照，独立 Chromium、390×844、DPR2、触摸，保留图片尺寸 | c41 主题目标 469 → 24，隐藏右栏 445 → 0；代码横滚及固定图加载均从 1 次缓存重建变 0 | 属于工作量计数，不等于 INP 或固定毫秒收益；正文标题高亮的 444 个独立观察目标保持 |

最新一轮同时保留了正向对照：表格真实横滚仍更新缓存，未知尺寸图真实加载并增高仍更新；390 → 1440 → 390 时可见右栏被重新纳入 / 排除。不能只验证“没有再计算”，还要验证“该计算时仍会计算”。

视觉对照为同输入、仅替换页面 JS 的 10 组截图：8 组全像素一致；其余 2 组仅手机右上主题按钮的动画中段不同，正文及亮暗终态一致。**全动画中段的全像素一致断言并未全部通过**，不得将其改写成“逐帧效果完全相同”。独立浏览器的动态取样和控件 Shadow DOM 动画同步仍有限制。

最终站点有 43 个地址状态检查及 5 组代表性交互 / 截图通过；它不等于 43 章逐页交互，也不等于真实手机全程帧率验收。

## 5. 给后续 AI 的排查顺序

1. **先确定宿主约束。** 找到已有主题状态源、主题 CSS、按钮接入点、正文与滚动容器；问清是否必须精确原配色、圆形硬边、系统跟随和减少动态效果。不重复引入第二套主题状态。
2. **选真实反例。** 至少覆盖短页、最大代码页、图片 / 表格页、深滚动位置；手机触摸与桌面鼠标分开，不能只在开发电脑首页点击。
3. **建立一次可重放基线。** 记录浏览器版本、视口、DPR、触摸、CPU降速、图片成功 / 失败状态、样本数；区分点击到状态、点击到绘制机会、VT ready、最长帧、布局和观察器耗时。不要把双 rAF 命名为 INP。
4. **分离成本来源。** 先直接切主题不播放页面揭示，再比较 VT / 轻量路径；检查样式重算、Layout、Paint、PrePaint、相交计算和事件脚本。资源隔离用于消除网络噪声，但最终仍需真实资源验收。
5. **一次只改一条因果链。** 例如诊断性排除 token 主题规则，或暂时关闭主题观察器，确认主因后再实施保留效果的最小修复；实验副本不等于最终产品。
6. **先去冗余，再加机制。** 优先移除无意义包装与错误失效关系；然后做准确占位和局部观察。不要先加更多定时器、更多全局观察器、全页 `will-change` 或全章几何缓存。
7. **正反向一起测。** 亮→暗、暗→亮、快速反切、主题中开抽屉、滚动后立即切、图片在途、resize、系统主题变化、减少动态效果、打印、搜索、锚点和键盘焦点都要有对应检查。
8. **构建与发布单独验收。** 测过源码不等于发布产物正确；检查语法、构建退出码、资源版本，再检查代表性线上交互和截图。保留失败证据；达到停止条件后收尾，不为追求漂亮数字无限重复试验。

## 6. 不同页面选择不同策略

| 页面类型 | 建议起点 | 额外检查 |
| --- | --- | --- |
| 短页面 / 普通后台 | 使用既有主题状态，先直接切换；若需要硬边圆形揭示，再验证 VT | 不默认启用长文缓存、DOM清洗或内容占位 |
| 超长静态文档 / 大量代码 | 手机优先评估轻量揭示；优化生成器与准确离屏占位；局部目标观察 | 代码查找、复制、打印、远处锚点、行高及全文高度 |
| 动态 SPA / 持续增删内容 | 接入现有组件状态与路由生命周期；只在相关内容变化时定向失效 | 组件卸载清理、过期回调、字体加载、路由返回及滚动恢复；不能用一次性静态索引 |
| 虚拟列表 / 无限滚动 | 复用列表已知的可见项和尺寸信息，不另扫整页 | 项复用后的坐标、内容变化、滚动容器并非 window |
| 画廊 / 视频 / Canvas / 图表 | 由媒体或绘图组件响应主题；页面揭示只包必要范围 | 不给媒体做整页反转；图表重绘与页面动画分别计时 |
| 强调无障碍 / 低动态页面 | 尊重 `prefers-reduced-motion`，直接完成状态与配色 | 无需为减少动态效果创建 VT 或涟漪；按钮语义、焦点和状态仍必须正确 |

移植完成的标准不是“按钮能动”，而是：状态唯一且可持久化，配色与揭示正确，长页没有新增全章点击计算，正常滚动 / 查找 / 打印 / 锚点仍可用，并在目标移动设备上留下可复核的证据。
